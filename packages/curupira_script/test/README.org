* Test Organization

** Test-Driven Development (TDD) Approach

This test suite is organized to support TDD:

1. *Phase 0 tests* - Tests that pass NOW (basic API, error handling)
2. *Phase 1 tests* - Tests tagged with =:phase1= that guide implementation
3. *Skipped tests* - Tests tagged with =:skip= for future features

** Running Tests

#+begin_src shell
# Run all tests (will show Phase 1 failures)
mix test

# Run only current phase tests (all should pass)
mix test --exclude phase1

# Run Phase 1 tests only (to guide implementation)
mix test --only phase1

# Run specific test file
mix test test/curupira_script_test.exs

# Run specific test by line number
mix test test/curupira_script_test.exs:42
#+end_src

* Adding New Tests

When adding tests:

1. *Phase 0 tests* - No tags, should pass immediately
2. *Phase 1 tests* - Add =@tag :phase1= above the test
3. *Future tests* - Add =@tag :skip= above the test

Example:

#+begin_src elixir
describe "new feature" do
  # Current phase - should pass
  test "basic behavior" do
    assert true
  end

  # Phase 1 - guides implementation
  @tag :phase1
  test "advanced behavior" do
    assert {:ok, _} = CurupiraScript.some_feature()
  end

  # Future - not ready yet
  @tag :skip
  test "experimental behavior" do
    assert {:ok, _} = CurupiraScript.future_feature()
  end
end
#+end_src
